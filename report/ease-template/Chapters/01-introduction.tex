\section{Introduction}
\label{sec:introduction}

PyPI and similar open-source package registries are a common vector for
software supply-chain attacks: attackers publish packages that imitate
popular libraries---through typosquatting, name squatting, or dependency
confusion---and execute malicious code during installation~\cite{duan2021supply,
ohm2020backstabber}. Since anyone can publish and installation scripts are
arbitrary code, automated detection must scale beyond manual review. Large
language models (LLMs) have emerged as a promising tool for this task: they
can read \texttt{setup.py} and other source files and judge whether a package
is malicious~\cite{ease2025rag}.

LLM-based detection, however, is not reliable on its own. An 8B-scale
instruct model recognizes overt malware, but misses subtle cases such as
obfuscated droppers and typosquats whose installation scripts look
innocuous~\cite{ease2025rag}. Retrieval-augmented generation (RAG) is a
natural remedy: before classifying, the model is shown similar examples
retrieved from a corpus of known malicious packages~\cite{ease2025rag,
crag2024}. The closest prior study, however, reports a negative result:
augmenting LLMs with retrieved knowledge bases built from YARA rules,
GitHub security advisories, and malicious code examples did not reliably
improve detection, while few-shot learning was markedly more
effective~\cite{ease2025rag}. That study coupled retrieval to specific
knowledge sources and a single retrieval mechanism, so it remains unclear
whether retrieval is fundamentally unhelpful or whether \emph{how} retrieval
is performed---sparse, dense, hybrid, behavior-based, or contrastive---is
what determines its value.

In this paper, we compare seven pipelines that differ only in the retrieval
strategy: no retrieval, dense, sparse (BM25), hybrid fusion, behavior-summary,
contrastive, and behavior-summary plus contrastive. We fix the generator
(\texttt{Llama-3.1-8B-Instruct}), the knowledge base (the training partition
of the EASE 2025 dataset~\cite{ease2025rag}), the prompting, and the decoding
parameters, so that observed differences are attributable to the retrieval
strategy alone. Our main findings are:

\begin{itemize}
    \item Retrieval substantially improves detection. Malicious-class F1
    increases from 0.888 without retrieval to 0.97 with dense or sparse
    retrieval, driven by recall.
    \item Sparse retrieval is as strong as dense retrieval: BM25 is within
    0.4 F1 points of a 4B embedding model, with no learned components.
    \item Contrastive retrieval, which shows the model both malicious and
    benign reference examples, reduces the false-positive rate to 0.1\% at
    0.948 recall.
    \item Retrieval over AST-derived behavior summaries is lossy and
    hurts performance, with F1 falling below the no-retrieval baseline.
\end{itemize}

We release the raw per-sample outputs of all seven pipelines and the
evaluation scripts as a replication package.
